# SafePulse · 职业疲劳智能预警监测系统

基于 [需求文档](../职业疲劳智能预警监测系统_PRD.md) 完成的可交互 MVP。项目使用 React + TypeScript + Vite 构建，包含员工端与管理端的核心业务闭环：

**监测 → 多模态测评 → 风险分级与解释 → 预警 → 干预 → 复测 → 报告**

> 当前版本为前端 MVP 演示，使用合成数据与浏览器 `localStorage` 持久化；不连接真实可穿戴设备、不做医疗诊断。

## 启动

```bash
cd fatigue-monitor
npm install
npm run dev
```

打开终端提示的本地地址，默认通常是 `http://localhost:5173`。

也可以直接使用角色入口：

- 员工端：`http://localhost:5173/?role=employee`
- 管理端：`http://localhost:5173/?role=admin`

生产构建：

```bash
npm run build
npm run preview
```

生成可直接双击打开的单文件 HTML：

```bash
npm run build:html
```

输出位置：

- `fatigue-monitor/dist-standalone/index.html`
- 工作区根目录副本：`SafePulse-职业疲劳监测系统.html`

单文件版本在 `file://` 环境下自动切换为 HashRouter，并支持 `localStorage` 不可用时降级为内存模式。

## 已实现功能

### 员工端

- 今日状态主页：当前风险等级、风险分、主要因素、状态说明
- 生理状态：HRV、心率、基线偏差、设备状态与数据质量
- 疲劳自评：VAS-F、KSS、POMS 结果与最近测评
- 今日班次：白班/夜班、起止时间、连续工作天数、加班
- 个人趋势：7 天风险/HRV 趋势、阈值线、事件标记
- 风险解释：贡献因素、风险预测、干预建议、数据质量
- 干预与恢复：预警原因、恢复方式、休息计时、复测、效果反馈
- 我的记录：测评、预警、干预历史与数据访问说明
- 深色模式与移动端底部导航

### 多模态测评

- 快速测评：生理数据 + VAS-F（18 项）+ KSS + PVT
- 完整测评：快速测评 + POMS-SF（30 项）+ VST + AX-CPT
- 测评会话：步骤导航、进度、设备检查、有效性校验、结果汇总
- PVT / VST / AX-CPT 为可交互演示版，PVT 缩短为 10 次试次
- 测评结果自动更新风险快照，并生成测评报告

### 管理端

- 风险管理驾驶舱：KPI、风险等级分布、组织趋势、班组/班型对比、最新预警、主要因素、优先关注员工
- 员工管理：搜索/筛选、新增员工、导出 CSV、停用/启用
- 员工详情：风险趋势、生理、主观、认知、预警、干预记录
- 风险名单：按等级/班组/班型筛选，批量提醒，分配干预
- 预警中心：预警列表、触发证据、处置时间线、确认、升级、分配干预、解除、标记误报
- 班组分析：班组高风险占比、班型热力图、动态洞察、对比明细
- 干预管理：任务创建、开始、完成、取消、复测、效果记录
- 报告中心：周报/月报预览、报告生成、打印/导出入口、报告历史
- 系统设置：阈值、模型权重、响应时限、通知规则、角色权限、数据保留

## 演示路径建议

### 1. 员工高风险处置闭环

1. 从首页或 `?role=employee` 进入员工端。
2. 查看首页当前风险（演示员工：张伟，高风险）。
3. 进入「干预与恢复」→ 开始 20 分钟恢复性休息。
4. 点击「演示：立即完成」跳过等待 → 提交复测。
5. 返回首页，风险分和风险等级已更新，预警同步解除。

### 2. 快速测评

1. 进入「多模态测评」→「快速测评」。
2. 完成 VAS-F、KSS 与 PVT（演示版约 30 秒）。
3. 生成风险结果并查看测评报告。

### 3. 管理端预警中心

1. 通过顶部角色切换或 `?role=admin` 进入管理端。
2. 进入「预警中心」，选择严重风险预警。
3. 确认预警、分配干预、查看处置时间线。
4. 进入「员工详情」查看生理/主观/认知趋势。

## 数据说明

- 员工、预警、干预、测评数据均为合成数据，位于 `src/data/mockData.ts`。
- 当前员工的测评、干预、风险变化会写入浏览器 `localStorage`（键名 `ofmp-demo-state-v1`）。
- 侧边栏「重置演示数据」可恢复初始场景。
- 风险分由生理、主观、认知与工作负荷加权计算，具体逻辑位于 `src/lib/risk.ts`。
- 所有健康相关数据仅用于演示，不构成医疗诊断。

## 技术结构

```text
src/
├── components/         # AppShell、通用 UI、图表、注意力任务
├── data/               # 合成员工/预警数据、量表和测评题目
├── lib/                # 风险分级、评分与格式化工具
├── pages/
│   ├── employee/       # 员工端
│   └── admin/          # 管理端
├── store/              # 全局演示状态与业务动作
├── App.tsx             # 路由
└── index.css           # 设计令牌、页面与响应式样式
```

## MVP 边界

以下能力未在当前演示中实现：

- 真实可穿戴设备接入、真实账号体系与 SSO
- 后端数据库、真实通知渠道、PDF/Excel 文件生成
- POMS 等量表的版权授权与正式本地化验证
- 生产级算法验证、医疗器械/职业健康合规评审
- 真实排班、HR、职业健康系统集成

正式实施前需完成隐私影响评估、数据授权、安全审查、算法验证和职业健康专业人员审核。

## 设计说明

- 风险等级使用固定语义色，同时配合图标与文字，不只依赖颜色。
- 图表使用单轴、2px 折线、细网格与悬浮提示，并提供数据表替代。
- 管理端以聚合数据为主，小样本班组不展示可识别聚合结果。
- 严重风险不能由员工自行关闭，处置记录保留审计轨迹。
